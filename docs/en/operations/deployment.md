# Deployment Recommendations

EyvesCloud can run directly on the host or behind a reverse proxy. In production, set up access control before opening it to administrators. Both single-panel deployments and "Controller-Agent" multi-node deployments are supported.

## Service Exposure

The default web port is `8999`:

```text
http://YOUR_SERVER_IP:8999
```

Recommendations:

- Only allow fixed administrator IPs.
- Use a reverse proxy to configure HTTPS.
- Do not expose real login addresses in public docs or screenshots.

## systemd

Common commands:

```bash
systemctl status eyvescloud
systemctl restart eyvescloud
systemctl enable eyvescloud
journalctl -u eyvescloud -f
```

## Controller-Agent Multi-node Deployment

### Controller Node

Install the panel normally on the server that will act as the Controller. Any panel can act as a Controller.

### Worker Node

On the worker server, run the one-line install script generated by the Controller's "Node Management":

```bash
bash eyvescloud-agent-node1.sh
```

The script installs the binary, registers with the Controller, and configures the `eyvescloud-agent` systemd service. Alternatively, install the panel manually on the worker and start it in Agent mode:

```bash
eyvescloud agent --controller=http://MASTER_IP:8999 --install-key=INSTALL_KEY --name=node-1 --addr=http://NODE_IP:8999
```

### Network Requirements

- The worker must be able to reach the Controller's `:8999` over LAN/WAN (registration and heartbeat).
- The Controller must be able to reach the worker's `node.Address` (proxy view/operation of containers).
- Configure the worker's `--addr` with a publicly reachable address.

### Scaling Out Worker Nodes

Repeat "add node on the Controller → get the script → run it on the worker" to onboard any number of worker nodes. The Controller's "Node Management" page shows the online status, resources, and container counts of all nodes in one place.

## Firewall

At minimum, verify:

- The panel port is only open to trusted sources.
- NAT mapped ports are opened as needed.
- The SSH management port does not conflict with container mappings.
- IPv6 firewall rules are planned alongside IPv4.
- Ports between the Controller and workers (registration, heartbeat, proxy) are open.

## Backup

Back up regularly:

- The EyvesCloud configuration directory (including the SQLite database).
- The worker's `agent.json` (lets you restore access directly after replacing the worker's disk).
- Container configuration.
- Snapshots of critical containers or external data backups.
