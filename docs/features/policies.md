# 策略管理

策略管理（Policy Engine）提供基于监控指标的自动化调整能力。当容器指标超过阈值时，系统可以自动提升 CPU/内存/带宽，或在资源失控时自动关机。

## 策略组成

一条策略包含：

| 字段 | 说明 |
| --- | --- |
| 名称 | 策略名称。 |
| 指标（metric） | 监控指标：`cpu`（CPU 使用率）、`memory`（内存使用率）、`network_rx`（入站带宽）、`network_tx`（出站带宽）、`disk_io`（磁盘 IO）。 |
| 比较符 | `gt`（大于）等。 |
| 阈值 | 触发阈值。 |
| 动作（action） | `raise_cpu`（提升 CPU 核数）、`raise_ram`（提升内存）、`adjust_bw`（调整带宽）、`shutdown`（自动关机）。 |
| 调整量 | 每次提升的 CPU 核数 / 内存 MB / 带宽 Mbps。 |
| 冷却时间 | 触发后再次触发的最小间隔（分钟），避免频繁抖动。 |
| 生效范围 | `all`（全部容器）、`tenant`（指定租户）、`container`（指定容器）。 |
| 启用状态 | 是否启用该策略。 |

## 常见用法

### 高峰期自动提升资源

```text
指标：cpu 使用率 > 80%
动作：提升 CPU 核数 +1
冷却：10 分钟
范围：指定容器
```

适合业务高峰自动扩容，低谷期可配合手动或策略回缩。

### 资源失控自动关机

```text
指标：memory 使用率 > 95%
动作：自动关机
冷却：30 分钟
范围：指定容器
```

适合防止单个容器内存泄漏拖垮宿主机。

## 触发记录

「策略管理」页面下方展示历史触发记录，包括触发时间、命中的策略、容器和动作，便于回溯与调参。

## 相关接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/policies` | 列出策略与触发历史 |
| POST | `/api/policies` | 创建策略 |
| PUT | `/api/policies/{id}` | 更新策略 |
| DELETE | `/api/policies/{id}` | 删除策略 |

策略引擎周期性扫描容器指标并执行命中动作，所有触发均会写入审计日志。
